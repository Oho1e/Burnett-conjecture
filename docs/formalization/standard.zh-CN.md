# paper-results：第 1.2 版标准

保存日期：2026-11-15。本标准为投稿论文形式化的独立工作方案，不是期刊或 Lean 官方颁发的认证规则。它不覆盖或取代已另存的较严格全文版本。

## 覆盖范围

| 对象 | 本标准的要求 |
| --- | --- |
| 正文与附录中的定理、命题、引理、推论 | 全部纳入，不因不被主定理使用就自动排除 |
| 作为独立结果陈述的关键未编号数学断言 | 纳入；疑难处不能通过不编号来规避 |
| 上述结果需要的定义、技术事实和引用结论 | 准确表示并纳入证明依赖；已有形式证明可复用 |
| 证明中的展开、代入、移项及例行计算 | 在实际 Lean 证明段中完成，不要求逐行单建 theorem |
| 背景事实、例子、反例、备注 | 若是正式结果、实际依赖或被明确宣称已验证，则纳入；否则不默认成为验证目标 |
| 历史叙述、动机、物理解释及与目标无关的旁述 | 保持正常论文质量核查，不自动另建形式化任务 |
| 可选的另一条证明路线 | 可以不形式化；不得声称该路线因此已经验证 |
| 原文明确的猜想、开放问题 | 保留原有认识状态，不冒充已证结论；其与成果说明的关系有歧义时交作者决定 |

“正式结果”由它在论文中承担的数学断言角色判断，不只看环境名称。无法确定某条 remark 是否包含独立贡献时，给出原文和理由让用户决定。不得为了降低工作量自行把结果降格为说明。

原文正式结果清单由源码逐项核对，不以仓库现有 theorem 列表倒推。相同结果的重复陈述可合并；依赖关系、定理特例或推论要有实际可核对的 Lean 证明归属。

## 四个独立维度

| 维度 | 本版本的取值 |
| --- | --- |
| 覆盖范围 | 全部正式数学结果及必要依赖；不是全文每句数学文字 |
| 证明路线 | 验证命题；允许替代证明，不默认认证原文每条路线 |
| 数学及计算信任 | 依赖闭合是推荐完成目标；具体信任决定按项目记录，当前工具仅实现标准三公理配置 |
| 工程质量与确认 | 可复现的文章专用代码；不默认 mathlib 投稿标准；独立代理复核后由用户/作者确认 |

选择本版本不会自动批准一个尚未决定的信任扩展，也不会授权改文章、安装技能或发布到远程。

## 完成与进度

- `development`：定义、证明或对应关系仍在推进。
- `conditional`：已有形式推导，但有额外未证数学前提或尚未解决的解释问题。
- `verified`：全部正式结果及依赖在所确认政策下闭合，语义差异解决，实际机器证据及独立复核、作者确认齐全。

项目尚未最终选择信任政策时，工具和证明可以继续使用，但不能把完成说明写成用户已经接受该配置。项目已有明确选择时直接沿用，不受模板或其他会话的待决字样影响。若选择保留未形式化文献前提作为最终交付，只能给明确的条件性说明；应另存相应标准或经用户决定修订，不能静默沿用闭合完成的措辞。

本版本不签发“只完成主定理”的整套完成标签。局部完成可以精确报告工作进度。发现正式结果缺口时继续修复或记录障碍，不能自动从清单删除它。

## 成果说明与标签

达到全部条件后，可以写：

> 本文该版本的全部定理、命题、引理和推论，以及清单列明的关键未编号结果，均已在 Lean 4 中形式化。原文对应、信任说明、固定版本及复现方法见配套代码仓库。

标签示例：`Lean verified — all formal results`。必须链接固定文章版本、固定代码提交和完整对应清单。避免只写“全文所有内容均已验证”，因为本标准不默认覆盖无关旁述或所有可选证明。

这是项目自行作出的范围说明，不代表普通数学物理期刊独立审查了全部代码。默认分支的绿色 build 徽章只表示机械检查状态。

## 版本绑定

项目清单写入 `standard.id: paper-results`、`standard.version: "1.2"`，并填写本标准文档实际 SHA256。标题、模板和项目清单使用同一版本号，不另用版本1来代表本修订版。

第1.2版沿用第1.1版的数学范围与完成目标，明确增量复核、确认继承和 GitHub 工程接入，并加强维护测试的失败原因判定。标准要求发生实质变化时另存新版本；已有文章项目切换版本须由用户明确决定并记录影响。其他标准的要求不因本版本发布而自动改变。
