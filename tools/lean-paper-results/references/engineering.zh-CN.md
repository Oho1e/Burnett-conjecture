# 工程接入与机械检查

本技能可独立携带，运行脚本只需要 Python 3.10+ 标准库及目标项目已经配置好的 Lean/Lake。沿用已有项目规则和等效检查，不为接入技能迁移目录或更新依赖。

## 新建或绑定论文仓库

新论文工程可以参照 [VectorFieldMethod 的锁定快照](https://github.com/Oho1e/VectorFieldMethod/tree/29807637096adbed7ee08b31a1e3c360123b3f3d) 的组织方式：根目录的库入口及命名空间目录、按数学层次组织的模块、`docs/statements/` 中的完整数学陈述和逐字 Lean 声明、工具链及依赖锁、构建 CI。该快照是设计参考，不声称已核实当前远程默认分支。

按实际需要建立以下结构，已有等效目录时直接沿用：

```text
<PaperLean>.lean                 库入口
<PaperLean>/                    定义、技术引理及论文对应结果
paper/                          已获准保存的原文快照及来源哈希
docs/statements/                数学陈述、上下文、实际 Lean 类型与原文定位
docs/formalization/             同一份范围清单、复核记录和标准快照
lean-toolchain                  固定 Lean 版本
lakefile.toml / lakefile.lean    实际构建及依赖配置
lake-manifest.json              实际依赖锁
scripts/check_paper.py          目标存在、来源及传递公理审计
.github/workflows/              适配本工程的 CI
README.md                       原文身份、真实状态、构建与复核入口
```

当前检查器按 `<repo>/Foo/Bar.lean` 定位模块 `Foo.Bar`；模板采用根目录模块结构。已有 `Lean/` 子工程可将该子工程作为 `--repo` 根并对齐配置；自定义 `srcDir` 需先适配并实测，不能只移动文件后假定脚本支持。

Lean/mathlib 版本按实际兼容性固定，接入已有工程时保留其 pin。参考库的 `ForMathlib/`、全库警告当错误和探索文件零 `sorry` 不成为文章项目的默认义务。README 的目标范围、已完成部分、未闭合接口及复核状态分别如实记录；不需要每次建库都发 release 或先贡献上游。

本轮已授权远程建库或推送时，核对 owner/name、可见性与准备提交的文件后执行，观察已启用 CI 的真实运行；没有相应指令时先做本地工程。仅将文章工程所需源码、配置与适当文档提交；排除凭据、构建缓存及无关工作区文件。原文的分发范围与本轮授权一致。

尚无论文目标声明时，可以先做独立标识的工程初始化检查。原检查器拒绝空目标清单；不要塞入 `True`、`rfl` 或无关引理冒充文章目标来获得绿色证明检查。存在实际目标后，执行精确目标审计，局部机器通过仍是开发证据。

## 接入已有仓库

1. 按需合并 `assets/repo-template/` 的文件，不覆盖已有配置。
2. 将本技能 `scripts/check_paper.py` 复制到目标仓库相同位置。
3. 填写真实文章身份和全部正式结果清单；保留 `standard.id`、`standard.version`、标准文档哈希及明确的 `scope.coverage`。
4. 在固定 Lean/mathlib 下运行：

```powershell
python scripts/check_paper.py --repo .
```

本地 SDK 可用 `--lake 'D:\path\to\lean-sdk\bin\lake.exe'` 指定。脚本不会初始化项目或更新依赖。完全无外部依赖的新项目可以先运行一次 `lake build` 生成 manifest；含 mathlib 的项目先按固定版本配置依赖和缓存。不要为解决缓存问题擅自 `lake update` 或删除共享 `.lake`。

Windows 辅助脚本若需要回显中文或 Lean Unicode 输出，应显式使用 UTF-8。若临时 PowerShell 包装脚本被执行策略阻止，可直接运行上述 Python 入口；不要求用户为一个复现包装器改变系统策略。恢复后以实际执行到的命令、退出码及日志为准。

## 清单含义

- `standard` 固定所采用标准；改变标准或版本须记录用户决定，不能通过换一个 coverage 字段静默降低完成要求。
- `scope.kind: paper-results` 是现有机械脚本支持的技术枚举。本包用 `scope.coverage: formal-results-and-dependency-closure` 和标准标识区分它与其他范围；不能只看 `kind` 猜测认证含义。
- `targets` 列出必须找到并检查的全部最终定理。一个原文结果有多个目标时拆为子编号；模块名写实际定义模块。
- `inventory` 对应原文正式结果及必要定义/依赖。结果必须从原文清点，不能只登记已写成 Lean 的部分。已有库定理可以直接映射，例行步骤可以合并为证明段。
- 模块和声明名目前支持 ASCII 点分标识符。Unicode 名称可增加普通 ASCII 的论文对应定理，或适配并实测脚本，不能直接删目标。
- 模板中全零文章哈希表示未配置，检查器会拒绝。主文件及多文件源的实际哈希由来源核对记录提供。

最终构建覆盖清单中的所有实现模块。可以用一个最终入口模块导入这些模块，并在该入口定义一个清单目标；已有等效构建证据也可沿用。独立定义或计算如果不进入任何目标的证明依赖闭包，还须实际查询公理或用已有全量检查核对其本体，不能仅凭编译成功就视为无占位。

## 检查器能证明什么

脚本显式构建目标模块，确认目标存在且确为 theorem、定义模块正确，并审计其传递公理依赖。标准配置只允许 `propext`、`Classical.choice`、`Quot.sound`。生成的审计文件保持普通 Lean 文件，不加 `module`，以保留所需证明可见性。

输出 `.paper-verification/` 包含运行版本、构建、公理和实际类型日志以及 `result.json`。实际 Lean 与标准版本 pin 不一致时拒绝；custom/nightly 的身份需另行核对。哈希按实际字节计算，Windows 与 Linux CI 应采用一致行尾；模板 `.gitattributes` 可用于新项目，接入旧项目先检查原策略。

脚本只输出机器状态。它不验证文章原文件的哈希，不判断全部结果是否登记、自然语言是否对应，也不判断标准或信任政策是否已批准。因此 `paper_hash_verified` 和 `semantic_correspondence_verified` 明确为 false；人工/代理的相应复核另有记录。局部 `selected-results` 清单可以用于开发检查，但不能满足本标准的完成要求。

源码快照排除依赖、工具和输出目录；依赖 manifest 哈希不保证本地 `.lake/packages/` 未修改。完成证据须从干净检出和固定来源依赖复现；路径依赖须有可复现来源/版本或内容哈希。固定来源预编译库属于通常工程信任，独立内核重检属于可另加的检查，不声称本工具已执行。

## CI 与复用证据

模板 CI 准备固定工具链与可用的 mathlib 缓存，然后运行精确目标检查并保存生成证据。它只有读取仓库的权限，不签发验证标签。点开头的证据目录已显式允许上传隐藏文件。若本轮已启用远程 CI，其完成证据须包括真实运行；解析 YAML 不等于该 CI 已执行。本地交付先使用本地复现证据，不因此新增远程操作。公开标签仍按标准绑定固定文章版本与代码提交。

本版在 Lean 4.24.0 上实际重跑20项检查器用例，并增加错误失败阶段不能替代预期公理拒绝的判定回归；检查器逻辑保持不变。维护负例同时检查预期阶段及关键诊断。这是工具维护检查，文章项目不需逐篇重复整套用例。当前测试与复用边界见包外层验证记录；不据此声称 Lean4.35 或某篇论文已验证。

本标准不默认要求全量警告当错误、整仓库探索草稿零 `sorry`、mathlib API 泛化或上游贡献流程；正式结果及其所需定义/依赖不能有未披露缺口。
