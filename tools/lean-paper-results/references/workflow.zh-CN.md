# 正向实现与反向核验工作流

本流程对应 `paper-results` 第 1.2 版。范围与完成含义以 [标准定义](standard.zh-CN.md) 为准。

```text
锁定原文与结果清单 → 建立或接入工程 → 数学陈述及定义 → Lean 声明与证明
   ↑                                               ↓
   └──── 与原文比较 ← 独立读出的数学命题 ← 实际类型与定义
```

另从主目标反推依赖，再按依赖顺序实现。依赖规划不代替反向语义核验。

## 1. 固定原文与结果清单

首次建立文章范围时，读取锁定文章正文及附录、实际源码和仓库规则，记录版本、文件 SHA256、Lean 工具链和依赖锁；多文件论文保留实际文件清单及哈希。续接时利用已有范围记录，按本轮任务及变化补读相关材料；已有范围依据不足时补足相应核对，不默认每次重读全文。

逐项列出正文及附录的全部正式结果和关键未编号断言；按标准判断备注、例子是否本身属于结果或必要依赖。明确不属于验证目标的材料可以简短说明类别，无需给每个历史句子单建排除记录。有实质歧义时提供原文交用户决定。

在 `docs/formalization/scope.json` 或项目已有等效文件中写入标准标识。沿用已有记录，不建立多份重复账本。

## 2. 建立或接入 GitHub 论文工程

确定本轮文章工程的本地位置、仓库 owner/name 和可见性。已有合适仓库时接入；没有远程操作指令时先在本地推进，不要求每次任务另建仓库。本轮已有明确授权时直接沿用，缺少目标信息或登录条件时只说明相应缺口，其余独立工作继续。

参照 `VectorFieldMethod` 的数学分层、`docs/statements/`、固定版本和 CI 组织工程，具体结构见 [工程接入](engineering.zh-CN.md)。README 写明文章版本、目标范围、实际进度、构建命令和复核入口；模块依数学依赖组织，陈述文档保留完整上下文及实际 Lean 类型。文章专用代码不因此增加 mathlib 上游要求。

论文快照、工程入口、配置和准确的状态文档准备好后，在已授权且目标明确的情况下创建或绑定远程库，推送实际版本，核对可见性并观察已启用 CI 的真实运行。把仓库 URL、固定提交及运行记录写入现有工程记录；凭据和构建缓存不进入仓库。首次证明尚未完成时可以先建库，CI 按实际阶段检查；初始化构建通过不计作论文目标证明通过。

选一个适中的重要结果贯通定义、证明、核验和构建，作为首个纵向切片；最终范围仍是全部正式结果。建库、编译和 CI 通过均不能单独支持整篇完成说明。

## 3. 从结果反推必要接口

检查主目标及各独立结果需要的分析、几何、代数和存在性事实。核实固定版本库的实际签名，区分已有形式证明、需要桥接的结果及尚无形式证明的接口。

按数学机制组织模块。耦合估计和 bootstrap 可以分工计算，但必须有共同闭合任务，不能让互为未证前提的两个接口分别宣称完成。若论文仅证明给定解的先验估计，不额外发起完整存在性理论开发；若结论是存在性，所需局部理论、延拓等依赖就不能隐藏。

## 4. 正向构造声明与证明

每个正式结果保留原文定位、完整数学陈述、Lean 名称与实际类型，以及新增技术条件的来源。重点核对：

- 对象、测度、范数、边界方向、符号及解概念。
- 量词次序、常数依赖和时间/参数的一致性。
- 正则性、可积性、有限性、支集、端点及实例参数。
- 原结论包含的存在、唯一性、连续依赖或衰减率是否齐全。

原文“足够光滑”等含糊条件逐项交用户决定，决定后再锁定该处精确建模。其余独立部分继续推进。

允许先用显式条件接口证明后续结论，标明消费者和未闭合项。最终论文对应定理从原文条件出发，实际构造和消除新增前提。参数或结构字段里包含待证结论时，即使公理检查通过，也只是条件推导。

可用替代证明和已有库定理。原文另有正式引理时，不能仅因新路线不再需要它就从全部正式结果清单删除；它仍需相应证明。

## 5. 独立反向核验

核验代理从实际 Lean 类型和重要定义独立写出数学含义，再比较原文及正向说明；理解符号时可按需查原文约定，独立判断不以正向说明代替。检查隐式参数、section 参数、typeclass、结构字段，不能只复制源码的一行 theorem 签名。

特别排查光滑解代替弱解、有限时间代替全局、逐时选择常数代替统一常数、a.e. 代替逐点，以及全定义导数/积分的默认值造成的意外陈述。对新造假设束做针对性相容性检查；零解例子不自动说明非零数据问题已正确建模。

核验者从锁定文章及附录独立核对正式结果范围，再与现有 inventory 双向比较，记录原文遗漏项、无原文对应项及合并映射的证明归属。沿用同一清单；不扩大到旧稿、备份或无关文件，不逐句建立背景材料排除表。复用前确认旧独立复核实际覆盖的锁定原文范围，并核明当前 inventory 仍完整承接这些结果；不能只因原文未变就沿用当前清单完整的结论。可复用已有独立清点事实，按需补查当前映射差异，不要求旧记录采用本轮模板或重做全部语义审计。将普通数学解释交用户或文章作者确认，记录确认范围、可识别的解释版本及未确认项；允许一次确认完整结果集合。代理同意不代替人类确认。

## 6. 机械检查与完成证据

构建清单目标及所需模块，执行目标传递公理检查。清单中未进入任何目标依赖闭包的独立定义或计算，另做适合它的本体与依赖核查；完整导入只保证编译，不自动排除未证占位。

附带脚本只报告机器状态，不判断原文覆盖、语义对应或信任政策是否已获作者接受。用 [复核模板](../assets/repo-template/docs/formalization/review.md) 记录实际发生的检查与确认。

语义证据绑定其适用的原文、实现、清单、工具链和依赖版本，可使用内容哈希或项目已有的等效版本记录。证据记录不写包含它自己的提交 SHA；本地保存内容快照和实际复现证据，远程 CI 或发布启用后另记录其实际运行与固定提交。

### 变更后的证据适用性

需要沿用旧结论时，先对照已有绑定检查输入。哈希变化用于发现变更，再按实际差异判断影响，不直接触发全文重审。历史记录保留；受影响记录标明仅适用于旧输入、当前待复核，不据此单独把数学状态改成 conditional。

- 定理陈述、重要定义、原文数学内容或解释发生实质变化时，重查受影响结果及相关接口。影响判断同时考虑实际类型、解释所需定义、实例、隐式参数、记号与约定；名字、签名文本或公理依赖图不足以单独说明含义未变。无需维护完整语义依赖数据库；影响暂不清楚时记录具体疑点，先补查相关部分，其余独立工作继续。
- 仅改变证明实现，且核实实际类型、相关定义与数学解释未变、信任仍符合已确认政策时，可继承原语义结论和作者确认；更新受影响构建、公理审计及输入绑定。是否有变化由实际检查确定，不能只采信“proof-only”描述。
- 仅改复核说明或排版且其数学内容、范围及实现未变时，更新记录即可，不重复作者确认。工具链或依赖改变时，在固定环境重新建立受影响机器证据，并检查其对解释的影响；本流程不授权自行升级依赖。
- 旧记录缺少绑定，或无法据旧绑定确定当前适用性时，先尝试用现有版本、来源、本地复现或对当前相关部分独立复核来建立依据；无法建立的部分说明证据不足。可以继续实现和独立核验，不因缺少旧记录就删除历史或冻结整个项目；当前完成说明只使用已有适用依据的结论。
- 经适用性核对，已有数学解释仍对应当前实际类型及其所需定义，且原确认范围覆盖本次使用部分时，可沿用已有作者确认。解释的数学含义新增、实质改变或确认范围需要扩展时，只将需要确认的部分交用户/作者；纯措辞或排版变化无需重复确认。实际确认及依据如实记录；覆盖关系暂不清楚时先补查现有记录，不自行补写同意。

必要定义的闭包覆盖或额外查询位置可写在现有 inventory 或复核记录中；不额外建立重复定义清单。

交付与本轮约定的本地或远程范围一致。远程建库和工程推送可以先于数学完成；使用整篇完成标签时仍须满足全部完成条件。保留旧版事实，文章或证明发生变化时记录新版本及证据适用范围。
